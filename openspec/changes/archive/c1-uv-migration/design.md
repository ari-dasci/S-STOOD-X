# Design: C1 — uv migration (env + dependency management)

> **Classification: Structural / safe** — config + docs only. No library/test/numerical logic.
> Edit-level design: this change's "architecture" IS the manifest. All decisions LOCKED in `proposal.md`.

## Technical Approach

Re-express the existing setuptools manifest in uv terms, pin the floating OpenOOD git HEAD to a commit, split dev tooling out of the published wheel into a PEP 735 dependency group, then generate and commit a CPU-only lockfile. No code path changes; the diff is three files (`pyproject.toml`, `.python-version`, `README.md`) plus one generated artifact (`uv.lock`). Canary = a clean `uv sync` that resolves OpenOOD at the pinned rev.

## Architecture Decisions

| # | Decision | Choice | Rejected alternative | Rationale |
|---|----------|--------|----------------------|-----------|
| D1 | OpenOOD source mapping | `[tool.uv.sources]` git rev pin; declare dep as bare `openood` in `[project.dependencies]` | Keep inline `git+https://…` URL in `dependencies` | uv requires the source in a separate table; bare name keeps the dep list clean and lets the lock pin the rev exactly |
| D2 | torch CUDA | CPU-only via PyPI default index; CUDA = README opt-in only, NOT in lock | `[[tool.uv.index]]` PyTorch CUDA in committed pyproject | Keeps committed lock reproducible on CPU CI/clones; GPU is author/user choice (locked decision #1) |
| D3 | Dev tooling location | PEP 735 `[dependency-groups] dev` (12 packages) | uv-legacy `[tool.uv] dev-dependencies` | Standard, portable across tools; `uv sync` includes `dev` by default; wheel build excludes it |
| D4 | Build backend | setuptools (unchanged) | hatchling | Out of scope (locked #4); no `[build-system]` edit |
| D5 | `.python-version` | `3.10`, committed | pin to 3.11/3.12 | Matches `requires-python>=3.10` floor; uv reads it as the default interpreter |
| D6 | `[tool.uv]` keys | Leave absent (defaults) | set `package=true`, `required-version` | `package=true` is default for a project; pinning uv itself is out of scope — avoid over-specifying |

## Data Flow

    .python-version ─┐
                     ├─→  uv (resolver) ──→ uv.lock (CPU-only, committed)
    pyproject.toml ──┤         │
      [project] deps (19)      ├─→ uv sync ──→ .venv (editable + dev group)
      [dependency-groups] dev  │                  │
      [tool.uv.sources] ───────┘                  ├─→ uv run python -c "import STOODX"
                                                 └─→ uv run pytest --collect-only

OpenOOD resolution path is the only non-PyPI branch: `openood` (declared) → `[tool.uv.sources]` (git rev `3c35632…`) → fetched at exact commit. torch/torchvision never touch that table (CPU PyPI).

### README install section — target structure (replaces lines ~41–67)

```markdown
## Installation

### Prerequisites
- Python >= 3.10 (managed automatically by uv via `.python-version`)
- uv (https://docs.astral.sh/uv/)
- CUDA (optional, for GPU acceleration)
- On systems without a C compiler toolchain: `build-essential` (required by `libmr`)

### Install (uv — recommended)
git clone https://github.com/ari-dasci/S-STOOD-X.git
cd S-STOOD-X
uv sync            # resolves editable package + dev group, CPU-only torch
uv run pytest      # or: uv run python -c "import STOODX"

### GPU / CUDA build (opt-in — does NOT change the committed uv.lock)
# Quick path (overrides index for this one command):
UV_PYTHON_INDEX_URL="https://download.pytorch.org/whl/cu124" uv sync
# OR add a named PyTorch index to your LOCAL pyproject.toml (uncomment when you need GPU):
# [[tool.uv.index]]
# name = "pytorch-cu124"
# url = "https://download.pytorch.org/whl/cu124"
# explicit = true
# Then: uv sync --extra-index-url pytorch-cu124
```

The committed `pyproject.toml` stays CPU-only (no `[[tool.uv.index]]`); the GPU snippet is documentation only. This keeps the lock reproducible and matches locked decision #2.

## Apply Sequence (ordered — for sdd-apply)

| Step | Action | Gate / canary |
|------|--------|---------------|
| **A** | Edit `pyproject.toml`: trim `[project.dependencies]` to 19; append `[dependency-groups] dev` + `[tool.uv.sources]`; convert OpenOOD URL→`openood`. Leave `[build-system]`, `[tool.setuptools]`, `[project.urls]` untouched. | TOML still parses (`uv` validates on next step) |
| **B** | Create `.python-version` with content `3.10`. | File exists |
| **C** | Run `uv lock` from repo root → generates `uv.lock`. | **CANARY**: lock resolves with `openood` at `3c35632…`, torch from PyPI. If it fails → see Risks, do NOT proceed to D |
| **D** | Run `uv sync` → installs editable package + `dev` group into `.venv`. | Exit 0, no resolver conflict |
| **E** | Rewrite README install section (lines ~41–67) to the structure above. | prose only |
| **F** | Verification gates: `uv run python -c "import STOODX"`; `uv run pytest --collect-only`. | import succeeds (env-level); suite collects with no import errors |
| **(commit)** | `git add pyproject.toml .python-version uv.lock README.md` — these four are the change. | — |

`uv.lock` and `.python-version` are the reproducibility artifacts; both MUST be tracked.

## Testing Strategy

| Layer | What | Approach |
|-------|------|----------|
| Resolve | `uv lock` + `uv sync` clean | The canary itself — no unit test; the lock IS the test |
| Import | `import STOODX` | `uv run python -c "import STOODX"` — env-level, not functional |
| Collection | pytest discovery | `uv run pytest --collect-only` — collection only, NOT pass/fail (`strict_tdd=false`) |
| Wheel purity | dev excluded from build | Structural: dev deps live only in `[dependency-groups]`, never in `[project.dependencies]` |
| Functional | — | **Out of scope** (deferred to C3) |

## Migration / Rollout

No data migration, no feature flags. Rollback = single-commit revert: restore prior `pyproject.toml`, remove `.python-version` + `uv.lock`, restore README lines ~41–67. Fully reversible (pure config/docs + generated lock; no logic change to revert).

## Risk Handling

| Risk | Reaction (design-level) |
|------|------------------------|
| **`uv lock` fails on OpenOOD dep-tree conflict** (e.g. OpenOOD pins `numpy<2` vs STOODX `numpy>=2.1.2`) — **highest-likelihood blocker** | **Preferred**: minimal resolution override via `[tool.uv]` override, e.g. pin the conflicting transitive to a compatible version scoped to the lock only (C1-scope, no STOODX pin bump). **Fallback (author sign-off)**: bump a STOODX pin — ⚠️ flag as potential C2 creep; only with author approval. **Never**: silently remove a STOODX runtime dep (violates non-goal). |
| `libmr` C-extension build fails (no compiler) | Document `build-essential` prereq in README (Step E); prefer prebuilt wheel. Non-blocking for resolution. |
| CPU-only lock doesn't exercise GPU paths | Accepted (`strict_tdd=false`); GPU is opt-in recipe, not gated here. |
| Published wheel install set shrinks (12 → dev) | Intended re-expression; dev install becomes the default `uv sync` (dev included by default). Flag for author awareness, not a defect. |
| Floating OpenOOD HEAD pre-fix breaks clean clone | This change FIXES it (pin `3c35632…`). |
