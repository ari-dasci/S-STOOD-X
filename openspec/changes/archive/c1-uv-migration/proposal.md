# Proposal: C1 — uv migration (env + dependency management)

> **Classification: Structural / safe** — no library logic, test code, or numerical/statistical behavior changes. First change of the C1→C2→C3 chain (force-chained). Review budget: 800 lines.

## Intent

Replace pip/setuptools + ad-hoc manual workflow with **uv**: one front for install/run/test, a committed `uv.lock` for reproducibility, and a pinned Python/toolchain. Eliminates the env-mismatch footgun (current shell is Py3.7/torch1.9 vs `requires-python>=3.10`) and the floating-HEAD OpenOOD dependency that today breaks any clean clone.

## Scope

### In Scope
- `pyproject.toml`: add `[tool.uv.sources]` (OpenOOD pin), `[dependency-groups] dev` (dev split). Keep setuptools backend. Convert `git+https://...OpenOOD` to `openood` runtime dep.
- `.python-version`: new file, content `3.10`, committed.
- `README.md`: rewrite install section (current lines ~49–67: `pip install -e .` + 6 manual `pip install` lines) → uv workflow (`uv sync`, `uv run pytest`) + CUDA opt-in note.
- Commit `uv.lock` (generated by `uv sync`).

### Out of Scope (non-goals → C2/C3)
- No src/ layout move, module rename, `__init__.py` export fixes, or OpenOOD-adapter extraction (→ C2).
- No build-backend swap (setuptools stays).
- No dependency removal (re-express/split only); no application/library/test logic change.
- No GPU lock (CPU-only default; acceptable since `strict_tdd=false`).

## OpenOOD Pin & Source

```toml
[tool.uv.sources]
openood = { git = "https://github.com/Jingkang50/OpenOOD", rev = "3c35632ee91b54b09d1f085d04f94744cece7d0b" }
```
Rationale: OpenOOD is imported at module top-level (`STOODX/STOODXPostprocessor.py`) and in every postprocessor test; today it floats at HEAD (currently unpinned `git+` URL). Pinning guarantees a reproducible resolution. Note: OpenOOD's own dep tree is heavy and may conflict with STOODX pins (see Risks).

## CUDA opt-in (documented, NOT in lock)

README documents an env-gated recipe, applied only by users who want GPU:
```bash
# opt-in CUDA build (does not affect committed uv.lock)
UV_PYTHON_INDEX_URL="https://download.pytorch.org/whl/cu124" uv sync
```
The committed `uv.lock` resolves CPU torch from PyPI.

## Approach

Re-express the existing manifest in uv terms, split dev tooling out of the published wheel, pin OpenOOD, then generate and commit the lock. Canary = a clean `uv sync` from scratch.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| OpenOOD heavy dep tree conflicts with STOODX pins (e.g. numpy<2 vs `>=2.1.2`) | High | Pin commit + canary `uv sync`; if conflict, lock a compatible numpy in resolution overrides (C1-scope) or bump pin (author sign-off). |
| `libmr` C-extension build fails (needs compiler toolchain) | Med | Document build-essential requirement in README; pre-built wheel preferred. |
| CPU-only lock does not exercise GPU paths | Low | Acceptable (`strict_tdd=false`); GPU is opt-in recipe, not gated here. |
| Published wheel install set shrinks (12 deps moved to dev) | Low | Intended; re-expression, not removal. Flag for author — doc build/dev install becomes `uv sync` (dev included by default). |
| Floating OpenOOD HEAD pre-fix breaks clean clone | High | This change fixes it (pin). |
